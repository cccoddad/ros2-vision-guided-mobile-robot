# 第 6 步：C++ 底盘驱动接口骨架

## 本步骤的边界

`base_driver` 是未来实机底盘 ROS 2 节点的 C++ 起点，使用 `ament_cmake` 和 `rclcpp`。本阶段没有打开串口或 CAN，也没有实现编码器、PID、PWM、里程计积分或 STM32 协议。因此它**不能控制真实机器人**。

它已经固定了未来必须兼容的 ROS 2 输入和状态语义：

- 订阅 `/cmd_vel`（`geometry_msgs/msg/Twist`），并将线速度、角速度限制在参数范围内；
- 发布 `/base_status`（`robot_interfaces/msg/BaseStatus`）；
- `fault_flags` bit0：超过 `command_timeout_s` 未收到命令；
- `fault_flags` bit1：硬件传输未启用。本阶段该位始终为 1，防止上层把节点误认为可驱动底盘；
- 未接收 STM32 编码器反馈时，故意**不发布** `/odom` 或 `odom -> base_link` TF，避免伪造位置数据。

STM32 的急停、通信超时、PWM 关闭和硬件故障处理仍是最终安全边界；这里的 ROS 2 状态只用于上层诊断，不能替代下位机保护。

## 无硬件生命周期与诊断模型

`base_driver` 现提供可单独测试的 C++ `DriverHealth` 状态模型，作为未来 `rclcpp_lifecycle` 节点的设计基础。它不会在当前阶段改变节点运行方式、创建诊断话题或访问传输设备。

- 状态顺序为：`unconfigured -> inactive -> active`；只有收到有效且无急停、无通信超时的状态后才允许激活；
- CRC 错误和乱序帧为警告，不能用于激活；
- 通信超时或 STM32 报告急停会转换为错误状态；急停优先级最高；
- 仅在重新收到有效、无急停、无超时的状态后，才允许从错误状态恢复到 `inactive`。

这是上位机的可观测性与生命周期设计，不是电机安全控制。真实 STM32 仍必须独立执行急停、通信超时与 PWM 关闭。

## 无硬件命令帧编码

`CommandFrameEncoder` 是不访问传输设备的 C++ 库。它复用 `protocol/` 的纯 C `SET_TWIST` 编码器，将受配置限制的 ROS 速度单位转换为协议的 `int16` mm/s 和 mrad/s，并保留调用方提供的帧序号。

- 超出 `max_linear_speed_mps` 或 `max_angular_speed_rps` 的输入会先限幅；
- NaN 或无穷速度会被拒绝，绝不生成二进制命令帧；
- 该库和单元测试不向 `Transport` 写入任何帧，当前 `base_driver_node` 也不会调用它。

因此它只验证未来上位机命令编码契约，并不表示 STM32 已收到命令、已执行 PID 或已驱动 PWM。

## 编译和单元测试

在 Ubuntu 中新开一个终端，执行下面整段命令：

```bash
source /opt/ros/jazzy/setup.bash
cd /mnt/hgfs/robot_project

BUILD_ROOT="$HOME/robot_ws_build"
colcon --log-base "$BUILD_ROOT/log" build \
  --build-base "$BUILD_ROOT/build" \
  --install-base "$BUILD_ROOT/install" \
  --packages-up-to base_driver \
  --event-handlers console_direct+

source "$BUILD_ROOT/install/setup.bash"
colcon test \
  --build-base "$BUILD_ROOT/build" \
  --install-base "$BUILD_ROOT/install" \
  --packages-select base_driver \
  --event-handlers console_direct+
colcon test-result --test-result-base "$BUILD_ROOT/build" --verbose
```

- **`ament_cmake`**：ROS 2 为 C/C++ 包提供的 CMake 构建规则。
- **`rclcpp`**：ROS 2 的 C++ 客户端库，负责节点、话题、参数和日志。
- **单元测试**：不启动硬件或 Gazebo，单独验证命令看门狗在 0.3 秒边界前后是否正确报告超时。

## 查看禁用状态

只有在未运行 `base_driver_mock` 或 Gazebo 的终端中，才可启动它。它们会使用同一个 `/cmd_vel` 和 `/base_status` 名称，不能同时作为同一台底盘的驱动源。

```bash
source /opt/ros/jazzy/setup.bash
source "$HOME/robot_ws_build/install/setup.bash"
ros2 launch base_driver base_driver.launch.py
```

另开终端执行：

```bash
source /opt/ros/jazzy/setup.bash
source "$HOME/robot_ws_build/install/setup.bash"
ros2 topic echo /base_status --once
```

预期 `fault_flags` 为 `3`：bit0 表示没有速度命令导致的超时，bit1 表示硬件传输禁用。这是保护性状态，不是硬件错误被修复。

## 下一阶段
