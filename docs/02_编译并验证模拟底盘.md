# 第 2 步：编译并验证模拟底盘

## 本步骤完成什么

这一阶段暂不启动 Gazebo，也不需要小车硬件。它只启动一个 ROS 2 节点，模拟差速底盘的基本运动，并发布：

- `/cmd_vel`：速度命令输入；
- `/odom`：模拟得到的位置、朝向和速度；
- `/tf`：`odom` 到 `base_link` 的坐标变换；
- `/base_status`：轮速、电压、命令年龄与故障位。

节点的安全规则是：超过 `0.3` 秒没有收到新的 `/cmd_vel`，就将期望速度归零，并在 `fault_flags` 设置 bit0（通信超时）。这对应未来 STM32 真实底盘必须具备的安全行为。

## 终端 A：编译并启动模拟底盘

在 Ubuntu 中打开终端，整段执行：

```bash
set -e

source /opt/ros/jazzy/setup.bash
cd /mnt/hgfs/robot_project

# 源码保留在 VMware 共享目录；编译产物放到 Ubuntu 本机目录。
BUILD_ROOT="$HOME/robot_ws_build"
mkdir -p "$BUILD_ROOT"

colcon build \
  --build-base "$BUILD_ROOT/build" \
  --install-base "$BUILD_ROOT/install" \
  --log-base "$BUILD_ROOT/log" \
  --packages-select robot_interfaces base_driver_mock \
  --event-handlers console_direct+
source "$BUILD_ROOT/install/setup.bash"

echo '=== 自定义接口 ==='
ros2 interface show robot_interfaces/msg/BaseStatus

echo '=== 启动模拟底盘；保持此终端打开，停止时按 Ctrl+C ==='
ros2 launch base_driver_mock mock_base.launch.py
```

术语说明：

- **colcon build**：按依赖顺序编译 ROS 2 包；这里会先生成消息接口，再编译使用该接口的模拟底盘。
- **source install/setup.bash**：让当前终端找到刚刚编译出的包；每次新开终端后都需要执行。
- **BUILD_ROOT**：编译产物所在的 Ubuntu 本机目录。ROS 2 生成消息代码时会创建很深的文件路径；VMware 共享目录 `/mnt/hgfs` 对这类路径有限制，所以源码可共享，编译产物应放在 `/home/china`。
- **launch**：把一个或多个 ROS 2 节点按配置启动；此处只启动 `base_driver_mock`。
- **TF**：坐标系变换树。`odom -> base_link` 表示机器人相对初始位置的运动。

`set -e` 的含义是“任一命令失败就停止执行本段脚本”。因此构建失败时会回到 `china@ubuntu:~$` 提示符，但终端本身没有退出。

成功时会显示类似：

```text
[INFO] [base_driver_mock]: Mock base ready: publishing /odom and /base_status; command timeout is 0.30 s.
```

## 终端 B：查看安全状态

保持终端 A 运行。按 `Ctrl+Shift+T` 新开一个终端标签页，然后执行：

```bash
source /opt/ros/jazzy/setup.bash
cd /mnt/hgfs/robot_project
source "$HOME/robot_ws_build/install/setup.bash"

ros2 topic echo /base_status --once
```

在尚未发送速度命令时，预期可看到：

- `fault_flags: 1`：bit0 为 1，代表通信超时；
- `command_age_s` 很大：模拟底盘从未收到有效命令；
- 左右轮速为 `0.0`。

这是安全逻辑正常工作，不是报错。

## 终端 B：发送一段模拟运动命令

再次在终端 B 执行下列命令。它会连续 3 秒以 `0.10 m/s` 前进，并以 `0.30 rad/s` 左转；3 秒结束后会自动停止发送命令。

```bash
source /opt/ros/jazzy/setup.bash
cd /mnt/hgfs/robot_project
source "$HOME/robot_ws_build/install/setup.bash"

timeout 3s ros2 topic pub --rate 20 /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.10}, angular: {z: 0.30}}"
```

命令结束约 0.3 秒后，再执行：

```bash
ros2 topic echo /base_status --once
```

此时应再次看到 `fault_flags: 1` 和接近零的轮速，证明命令停止后模拟底盘自动安全停车。

## 如果编译报错

将从第一条 `Error` 开始到终端末尾的内容复制给 Codex。不要删除已有的 `build/`、`install/` 或 `log/` 目录；它们能帮助定位包依赖或编译问题。本项目之后使用 `$HOME/robot_ws_build` 中的三类目录，不再受共享目录的文件名限制。
