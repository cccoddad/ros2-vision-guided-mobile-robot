## 当前接口和安全边界

- `parking_controller`：订阅 `/sim/tag_pose`，发布 `/cmd_vel`，提供 `/park_to_tag` Action。
- `base_driver`：订阅 `/cmd_vel`，发布 `/base_status`；未接入 STM32 时不发布伪造 `/odom` 或 TF。
- `robot_simulation`：把 Gazebo `/model/mock_mobile_robot/odometry` 桥接为 ROS `/odom`，并由模拟节点发布 `/sim/tag_pose`。
- STM32 仍应拥有急停、通信超时、PWM 关闭和硬件故障的最终控制权；本项目尚未连接串口、CAN、电机、编码器或相机。

## 继续开发前的快速复现

在新对话开始时，先执行以下命令复核当前源码和构建环境。它不修改系统设置；`source` 仅让当前终端识别 ROS 2 与已构建的软件包。

```bash
source /opt/ros/jazzy/setup.bash
cd /mnt/hgfs/robot_project

export ROS_LOCALHOST_ONLY=1
export ROS_DOMAIN_ID=42

BUILD_ROOT="$HOME/robot_ws_build"
git status --short
git log -1 --oneline
```

- `ROS_LOCALHOST_ONLY=1`：让 ROS 2 的 DDS 发现只在当前 VMware 虚拟机内进行，规避该环境的组播网络错误。
- `ROS_DOMAIN_ID=42`：把多个终端放进同一个 ROS 2 通信域；参与同一次测试的所有终端必须使用相同值。
- `git status --short`：确认没有未提交改动后再继续开发。

## 下一步：无硬件条件下的 C++ 传输适配层

下一阶段不连接真实串口，而是在 `base_driver` 内实现可替换的 C++ 传输抽象，并使用假传输（fake transport）喂入 `protocol/` 的 C 帧。这样可在硬件到货前验证：帧解码、序号、状态映射、超时和故障上报；不会触碰电机、STM32、串口或 PWM。

实现前已在 Ubuntu 终端复现相关构建和测试；随后完成了下列 SIL-only 功能，均不访问真实硬件：

1. `base_driver` 的 C++ `Transport` 接口与 `FakeTransport` 内存测试替身。
2. 复用 `protocol/` 的纯 C 解码器接收伪造 `BASE_STATUS` 帧，并映射到既有 `robot_interfaces/msg/BaseStatus`。
3. C++ GTest 覆盖正常映射、CRC 错误、乱序序号、通信超时和急停状态。

当前的验证命令如下；仅构建相关包和运行已有测试，不会删除任何目录：

```bash
source /opt/ros/jazzy/setup.bash
cd /mnt/hgfs/robot_project

export ROS_LOCALHOST_ONLY=1
export ROS_DOMAIN_ID=42

BUILD_ROOT="$HOME/robot_ws_build"

colcon --log-base "$BUILD_ROOT/log" build \
  --build-base "$BUILD_ROOT/build" \
  --install-base "$BUILD_ROOT/install" \
  --packages-up-to base_driver parking_controller \
  --event-handlers console_direct+

source "$BUILD_ROOT/install/setup.bash"

colcon test \
  --build-base "$BUILD_ROOT/build" \
  --install-base "$BUILD_ROOT/install" \
  --packages-select base_driver parking_controller \
  --event-handlers console_direct+

colcon test-result --test-result-base "$BUILD_ROOT/build" --verbose
```

下一阶段仍只能在硬件规格、串口参数和 STM32 固件准备完成后，再由用户明确授权接入实际传输；届时先验证下位机独立急停、通信超时和 PWM 禁用。当前 SIL `BASE_STATUS` 负载仅为测试格式，不是冻结的硬件协议。

## 需要硬件后才能继续的项目项

- 轮径、轮距、质量、摩擦等实测与标定；
- STM32 串口或 CAN 参数、编码器格式、电池与驱动器故障字段；
- 电机 PID、PWM、急停、看门狗和供电安全测试；
- 相机内参与外参标定、真实 AprilTag 检测质量与不同光照测试；
- 基于真实编码器的 `/odom`、TF、实车限速与停车距离验证。

这些项目均不能由 Gazebo 或当前模拟 Tag 结果替代。
